# Skills Index

Workflow and domain playbooks for the EasyDeL monorepo (44 skills). Start non-trivial work from
[run-research](run-research/SKILL.md), then layer the matching domain skill. See also
[AGENTS.md](../../AGENTS.md), [WORKSPACE.md](../../WORKSPACE.md), [Agent Guidance](../README.md), and
[Operational Runbooks](../ops/OPS.md).

## Core Workflow & Review

- **[run-research](run-research/SKILL.md)** — Base workflow for EasyDeL research, optimization, debugging, or multi-step implementation tasks that require hypotheses, experiments, evidence, and a clean handoff. Use when work spans multiple files, affects performance/numerics/runtime behavior, or needs repeated verify-and-adjust loops.
- **[test-workspace](test-workspace/SKILL.md)** — Select and run correct EasyDeL workspace checks. Use for affected-package test planning, accelerator (TPU/GPU) test env setup, the conftest guard that refuses computation tests on CPU (cpu_ok marker), import-layering checks, pre-commit behavior, hardware-bound test selection, Rust surgecore checks, and rejecting weak tests across libs/easydel, libs/spectrax, libs/ejkernel, libs/eformer, libs/eray, libs/surgecore, and libs/eyvan.
- **[generate-tests](generate-tests/SKILL.md)** — Generate repository-consistent tests for EasyDeL workspace changes — models, trainers, operations/kernels, eSurge, surgecore, data pipelines, infra sharding. Use when new behavior needs coverage or when asked to write tests; for choosing/running existing tests use test-workspace instead.
- **[review-pr](review-pr/SKILL.md)** — High-signal correctness review for EasyDeL pull requests or branch diffs. Use when asked to review a PR, review uncommitted changes, or audit a branch for bugs, package-boundary violations, testing-policy violations, or release/commit hygiene before merge.
- **[distributed-review](distributed-review/SKILL.md)** — Focused review of EasyDeL workspace changes that touch Mesh, NamedSharding, PartitionSpec, shard_map, axis policies, FSDP/TP/SP/EP, or pipeline parallelism (SPMD or MPMD). Use as a review pass whenever a diff mentions sharding, partitioning, mesh axes, or stage assignment.
- **[prepare-commit-pr](prepare-commit-pr/SKILL.md)** — Prepare an EasyDeL commit or pull request safely. Use for staging, pre-commit, import layering, focused test selection, PR summaries, branch hygiene, release-policy checks, subtree mirror warnings, and enforcing the no self-credit trailer rule.
- **[release-workspace](release-workspace/SKILL.md)** — Release or publish one of the seven EasyDeL uv workspace packages. Use for version bumps, dry-run releases, publish tags, standalone repo subtree mirror sync, package dependency pins, surgecore Rust/maturin releases, eyvan dashboard wheel staging, or pre-push release hygiene for easydel, spectrax, ejkernel, eformer, eray, surgecore, or eyvan.

## Docs & Tooling

- **[update-docs](update-docs/SKILL.md)** — Update EasyDeL workspace documentation when APIs change — regenerate Sphinx api_docs, fix hand-written package docs, keep AGENTS.md/WORKSPACE.md/skill references accurate. Use after renaming/moving/adding public APIs or when docs are reported stale. For bulk docstring passes use docstring-swarm instead.
- **[docstring-swarm](docstring-swarm/SKILL.md)** — Launch parallel workers to add and repair Google-style Sphinx-Napoleon docstrings across an EasyDeL workspace package — module, class, and function/method docstrings (public and private), expanding `**kwargs: Unpacked[TypedDict]` fields. Docstring-only diffs; never adds standalone variable/attribute docstrings or changes behavior.

## Skill Authoring Policy

Every EasyDeL skill routes the agent directly into live code and exact verification commands — never generic advice.
When creating or updating a skill:

- Use valid YAML frontmatter with `name` (matching the skill directory name) and a concrete, untruncated `description`
  (quote the value if it contains `: `). Keep frontmatter harness-agnostic — omit harness-specific keys.
- Declare specialization explicitly when the skill builds on `.agents/skills/run-research/SKILL.md`.
- Ground every cited script, flag, symbol, env var, doc, and repo-root-relative path (`libs/...`, `scripts/...`,
  `.agents/...`) in the live tree before writing it; omit unverified targets.
- Point infrastructure and hardware failure runbooks to `.agents/ops/OPS.md` rather than duplicating them.
- Prefer concise "First Reads" pointers over paraphrasing package docs, and follow `AGENTS.md` Golden Rule 4 (all JAX
  computation tests and benchmarks run on TPU/GPU; never claim CPU validation).
- Update `.agents/skills/README.md` (and `AGENTS.md` / `.agents/repo-map.yaml` when relevant) in the same change and
  verify with `uv run python scripts/check_agents_integrity.py`.
